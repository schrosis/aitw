# SDD のスキルの約束事

すべての SDD のスキル（`sdd-*`）が守る約束事です。チャットから呼ばれたときも、ugoke のワークフロー（`plan`）の
ステップから呼ばれたときも、同じように動きます。

## 段階

要件、設計、タスクの順に書きます。各段階では、前の段階で人間が承認した文書を正とします。

| 段階   | 書くスキル         | 検証するスキル        |
| ------ | ------------------ | --------------------- |
| 要件   | `sdd-requirements` | `sdd-validate-gap`    |
| 設計   | `sdd-design`       | `sdd-validate-design` |
| タスク | `sdd-tasks`        | `sdd-validate-tasks`  |

前の段階の文書がなければ、書かずに止めて、前の段階のスキルを案内してください。

## 作業の名前

スキルの引数は作業の名前（`<name>`）です。英小文字、数字、`-` だけで、`-` で始まりません。
名前がない、またはこの形でなければ、止めて名前を求めてください。

## 置き場

文書の置き場と読み書きのしかたは [storage.md](storage.md) に従ってください。ほかの場所に文書を書かないでください。

## 調べるもの

書く前に、次のものを調べてください。

- `README.md`、`CLAUDE.md`
- `docs/` の決定と検討事項（`decisions.md`、`decision-points.md`、`roadmap.md`、`backlog.md`）
- 関係する既存のコード

`docs/` の決定から判断できることは、人間に聞かずに決定に従ってください。

## 書いてよいもの

- 書くスキルは、その段階の文書だけを書く。コードとほかのファイルは変えない
- 検証するスキルは、何も書かない。結果を報告するだけにする

## 初回と差し戻し

- 文書がまだなければ、雛形に沿って全文を書く
- 文書がすでにあり、依頼に差し戻しの理由があれば、理由に沿って直すところだけを直す
- 文書がすでにあり、差し戻しの理由がなければ、書き直さずに止めて、何を直すかを求める
- 依頼に検証の結果があれば参考にする。ただし対応するのは、差し戻しの理由で対応を求められたものだけにする

## 人間に決めてほしいこと

人間に質問はしないでください。ワークフローのステップの中では、答えられる人がいないためです。
決めてほしいことは、文書の「未決の論点」の節に、背景、選択肢、おすすめとその理由を添えて書いてください。
人間は、文書を承認するか差し戻すときに答えます。なければ「なし」と書いてください。
タスクの文書には、この節を作りません。タスクの段階の論点は、報告にだけ書いてください。

## 書き方

- 日本語で、`docs/` と同じ文体で書く
- 推測で埋めない。わからないことは「未決の論点」に書く
- 同じことを複数の節に書かない

## 報告

最後に、次のことを報告してください。ワークフローは、この報告を承認の画面に出します。

- **変更:** 初回なら「初版」。差し戻しなら、理由ごとに何をどう直したか
- **未決の論点:** 論点の見出しと、選択肢とおすすめの要点。なければ「なし」

検証するスキルの報告は、そのスキルに書いた形に従ってください。
