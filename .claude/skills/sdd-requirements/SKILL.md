# sdd-requirements

作りたいものについて、要件の文書を書きます。要件には、利用者から見た振る舞いを書き、実装のしかたは書きません。

## 手順

1. [約束事](../../sdd/conventions.md) と [置き場](../../sdd/storage.md) を読む
2. 依頼から、作業の名前と、作りたいものを読み取る。初回で作りたいものがなければ、止めて求める
3. 約束事の「調べるもの」を調べる。作りたいものに関係する既存の機能、利用者に見える名前（コマンド、
   定義のキー、設定）、決定済みのことを確かめる
4. [EARS の書き方](rules/ears.md) と [雛形](templates/requirements.md) に沿って、下書きを作る
5. [書く前の関門](rules/review-gate.md) で下書きを確かめ、直せるものは直す。関門の確かめと直しは
   2 回までにする。それでも残る曖昧さは「未決の論点」に書く
6. 置き場の要件の文書に書く
7. 約束事の「報告」の形で報告する

## 要件と設計の分け方

要件に書くのは「何ができるようになるか」です。

- **要件に書く:** 利用者に見える振る舞い、入出力、エラーの扱い、範囲、利用者に見える名前（コマンド、
  オプション、定義のキー、設定）
- **設計に回す:** パッケージ、型、関数、ファイル、内部のデータの流れ、実現のしかた

受け入れ基準が、内部の部品の名前を出さずに書けるなら、要件に置きます。
