# sdd-tasks

承認された要件と設計を、実装のタスクに分けます。大タスク 1 つが PR 1 つになり、ugoke の `develop`
ワークフローが 1 回の実行で 1 つの PR を実装します。並べて進められる PR は、同じ Wave にまとめます。

## 手順

1. [約束事](../../sdd/conventions.md) と [置き場](../../sdd/storage.md) を読む
2. 置き場から要件と設計の文書を読む。どちらかがなければ止めて、書くスキルを案内する
3. [タスクの分け方](rules/tasks.md) と [雛形](templates/tasks.md) に沿って、下書きを作る
4. タスクの分け方の「書く前の関門」で下書きを確かめ、直せるものは直す。関門の確かめと直しは 2 回までにする。
   要件や設計が曖昧、または矛盾していてタスクに分けられないときは、タスクで埋め合わせず、
   どこを直すべきかを「未決の論点」として報告する
5. 置き場のタスクの文書に書く
6. 約束事の「報告」の形で報告する。未決の論点は、タスクの文書には節を作らず、報告にだけ書く

## develop との約束

`develop` は、タスクの文書をスクリプトで読みます。タスクの分け方の「形の決まり」を必ず守ってください。
形が崩れると、PR を拾えない、または違う範囲を拾います。
