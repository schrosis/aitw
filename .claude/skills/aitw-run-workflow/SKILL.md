# aitw のワークフローを実行する

チャットの相手（ユーザー）の代わりに aitw のワークフローを実行し、待機ステップの質問を中継する。
ユーザーはスマホから Remote Control で話していることがあるため、端末を前提にしない。

## コマンドの呼び出し方

- `PATH` に `aitw` があれば `aitw` を使う
- aitw のリポジトリでは `pnpm -s aitw` を使う。`pnpm build` 済みであること。pnpm が出すコマンドの行は標準エラーに出るため、標準出力の JSON Lines は崩れない
- プロジェクトのルート（`.aitw/` のあるディレクトリ）か、その下で実行する。`.aitw/` がない場合は、ユーザーにどのプロジェクトで実行するかを聞く

以下では `aitw` と書く。

## 前提の確認

1. `aitw daemon status` で常駐プロセスが動いているかを確かめる。動いていなければ、ユーザーに確認してから `aitw daemon start` で起動する。常駐プロセスの版が CLI と違うと言われたら、`aitw daemon stop` と `aitw daemon start` で起動し直してよいかを聞く
2. 実行するワークフローが決まっていなければ、`.aitw/workflows/` の定義を見せて選んでもらう
3. ワークフローの `inputs` の必須の値が足りなければ、ユーザーに聞く。推測で埋めない

## 実行の開始

```bash
aitw run <workflow> --input '<JSON>' --from-ai
```

- Bash の `run_in_background` で動かす。AI ステップやスクリプトに時間がかかっても、終わったら通知が来る
- 出力は 1 行に 1 つの JSON（後述）。最初の行の `workflowId` を覚えておく
- 終わったら最後の行を読んで、下の「最後の行の読み方」に従う

## 出力の読み方

各行の `type`:

| `type`                         | 意味                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------- |
| `started`                      | 実行が始まった。`workflowId` と `name`                                                      |
| `answered`                     | `inbox answer` の答えが受け付けられた                                                       |
| `stepStarted` / `stepFinished` | ステップの始まりと終わり。`stepFinished` の `outcome` は `succeeded`、`failed`、`cancelled` |
| `question`                     | 答え待ち。`workflowId`、`step`、`visit`、`message`、`answers`、`inputs`                     |
| `warning`                      | 実行は続くが、知らせるべき問題                                                              |
| `completed`                    | 実行が終わった。`executedSteps`                                                             |
| `failed`                       | 失敗した。`message`                                                                         |
| `cancelled` / `detached`       | キャンセルされた / 質問なしで切り離された                                                   |

最後の行の読み方と終了コード:

| 最後の行    | 終了コード | すること                                                       |
| ----------- | ---------- | -------------------------------------------------------------- |
| `question`  | 3          | 「質問の中継」に進む。実行は Temporal で待ち続けている         |
| `completed` | 0          | 実行したステップを添えて、終わったことを伝える                 |
| `failed`    | 1          | `message` をそのまま伝える。勝手に直したり、やり直したりしない |
| `cancelled` | 130        | キャンセルされたことを伝える                                   |

ステップの出力（スクリプトや AI の出力）は JSON Lines に出ない。ユーザーが中身を見たがったら、ステップが書いたファイルやリポジトリの変更を見て伝える。

## 質問の中継

1. `question` の `message` を、要約せずにチャットに出す。Markdown として読めるように整える
2. 答える項目（`answers`）を、選択肢や型がわかるように示す。`choice` は `options` を並べ、`required: false` の項目は省略できると伝える
3. ユーザーが席を外していそうなら（実行に時間がかかった後など）、PushNotification で知らせる。例: `develop の approve で答え待ち: 設計案の確認`
4. ユーザーの返事を、`answers` の型に合わせて JSON にする

答えるときのルール:

- **答えるのは、ユーザーが言ったことだけ。** 自分で判断して答えない。「たぶん OK だろう」で送らない
- 返事が曖昧なとき、`choice` の選択肢に当てはまらないとき、必須の項目が抜けているときは、聞き直す
- 自由入力の項目（差し戻しの理由など）は、ユーザーの言葉をそのまま使う。補足したいときは、送る前に案を見せて確かめる
- 複数の実行が答えを待っているときは、どの実行（`workflowId` とワークフローの `inputs`）のどの質問への答えかを、ユーザーと確かめる

## 答えを送る

```bash
aitw inbox answer <workflowId> --step <step> --visit <visit> --values '<JSON>' --from-ai
```

- `--step` と `--visit` は、`question` の値をそのまま使う。古い質問への答えは Workflow が拒否する
- `run` と同じく `run_in_background` で動かす。答えたあと、次の質問か終わりまで進み、同じ形の JSON Lines を出す。最初の行は `answered`
- 最後の行が `failed` で、`message` が答えの拒否（`Must be ...`、`is not waiting for an answer` など）なら、実行は待ち続けている。理由を伝えて、答え直してもらう
- 答えるたびに許可の確認が出る設定（`.claude/settings.json` の `ask` ルール）になっている。確認が出たら、ユーザーが承認するのを待つ

## ほかの操作

| したいこと                         | コマンド                                                                                                               |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 答え待ちを一覧にする               | `aitw inbox list --from-ai`（1 行に 1 つの `question`。読めない実行は `unreadable`）                                   |
| 端末を占有せずに始めるだけ         | `aitw run <workflow> --input '<JSON>' --detach`（答え待ちは `inbox list` に出る）                                      |
| 答えて、あとは常駐プロセスに任せる | `aitw inbox answer ... --detach`（常駐プロセスが動かしている実行だけ。`inbox list --from-ai` の `inDaemon` が `true`） |
| 止める                             | `aitw cancel <workflowId>`。必ずユーザーに確認してから実行する                                                         |

`aitw resume` は人が端末で追いかけるためのコマンドで、対話式の入力を求める。チャットからは使わない。

## 注意

- `aitw run` と `aitw inbox answer` を、`--from-ai` も `--detach` もつけずに実行しない。端末での入力待ちになって止まる
- 同じ実行に対して、`inbox answer --from-ai` を同時に 2 つ動かさない。後のほうは、先のほうが実行を追いかけているため失敗する
- 実行のキャンセル、常駐プロセスの停止と起動は、ユーザーに確認してから行う
