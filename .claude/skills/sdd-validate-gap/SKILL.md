# sdd-validate-gap

要件の文書を、既存のコードと決定に照らして検証します。結果は報告するだけで、文書もコードも変えません。
ギャップの調査の結果は、設計の段階（`sdd-design`）で使います。

## 手順

1. [約束事](../../sdd/conventions.md) と [置き場](../../sdd/storage.md) を読む
2. 置き場から要件の文書を読む。なければ止めて、`sdd-requirements` を案内する
3. [ギャップの調べ方](rules/gap-analysis.md) に沿って、既存のコードを調べる
4. 要件の文書の問題を、次の観点で確かめる
   - **矛盾:** `docs/decisions.md` の決定、既存の仕様、`CLAUDE.md` の規約と食い違うところ
   - **受け入れ基準:** [要件の関門](../sdd-requirements/rules/review-gate.md) の機械的な確かめを満たすか
   - **抜け:** エラーの扱い、境界の値、互換性など、書かれていない振る舞い
   - **範囲:** 作りたいものから外れた要件や、範囲の「含まない」に書くべきもの
5. 下の形で報告する

## 報告

- **判定:** 直すべき問題があれば `issues`、なければ `ok`
- **問題:** 問題ごとに、場所（節と番号）、内容、直し方の案。`ok` なら「なし」
- **ギャップ:** 問題の有無にかかわらず、ギャップの調査の結果。設計の段階が読む
